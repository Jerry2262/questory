# 任务状态机设计迭代记录

日期：2026-11-17
性质：内部记录，不放入面向人的设计文档。

## 目标

- 任务作废/恢复采用无记忆状态机：可见状态只由当前数据决定，不保存「作废前是什么」等历史。
- 每个任务只有四个可见状态：未完成、完成、未完成 + 作废、完成 + 作废。
- 关闭 = 完成 | 作废；关闭行变灰，删除线只表示作废。
- 父任务作废等价于所有后代任务作废；全子项作废时父任务自动作废。
- 作废任务下不允许新增任务或缩进任务；完成和未完成的父任务都可以新增。
- 移动（MOVE）只把象限顶层的整棵任务树移到同周另一个象限，不改变父子关系；当前实现只允许顶层任务移动。

## 犯过的错

1. 把父任务画成独立状态节点。父任务没有独立状态，它是子项状态的 Moore 投影；共用的是显示词汇，不是状态变量。
2. 上一版用「父任务 voided + 祖先覆盖 + doneBeforeVoid」表达状态，导致同一个界面状态有不同来源；用户明确要求统一、无记忆。
3. 状态机的迁移矩阵不完整：只画了会改变状态的迁移，没有列出自环、禁用和幂等事件。完整规格应覆盖全部 4 个状态 × 3 个事件（TOGGLE / VOID / RESTORE）。
4. 把父任务作废画成父节点的迁移。它实际是一次递归动作，迁移发生在所有叶子上，父任务只是投影重算。
5. 把 MOVE 和 INDENT 混在一起描述，写出「移入作废父任务时叶子继承作废」。MOVE 不改变父子关系；只有 INDENT/OUTDENT 才会改变父子关系，缩进到作废任务下应被拒绝。
6. 忽略了「关闭 = 完成 | 作废」的整行变灰规则，只把作废当删除线；完成行也应变灰。
7. 写了「新增任务继承父任务作废态」。正确规则是作废任务下不允许新增，因此不存在新增继承作废的场景。
8. 状态表示混用字符串枚举和布尔：`status: 'open' | 'done' + voided?: boolean`。统一成 `done: boolean` + `voided: boolean`，四个状态就是两个布尔的组合，不要字符串枚举。
9. 父状态表按条件组合穷举行优先，不易读；应改成结果优先：分别写 `done` 为真/为假的条件、`voided` 为真/为假的条件，父状态就是两个布尔的结果。
10. 父任务 `done` 的条件写成「所有直接子项 done」，漏了「存在一个 done」和「所有直接子项关闭」这两个条件；正确条件是 `(∃ c: done=true) ∧ (∀ c: closed=true)`，`closed = done || voided`。作废子项不应阻止父完成。

## 当前目标模型

- 叶子：`done: boolean` + `voided: boolean`，四个状态。
- 父任务：不存 `done` / `voided`；`voided = 所有直接子项 voided`；`done = (存在直接子项 done) ∧ (所有直接子项 closed)`，`closed = done || voided`。父任务只读取直接子项的两个布尔，不读取孙任务。
- 动作：
  - TOGGLE：未作废叶子 `done` 取反。
  - VOID：递归把子树所有叶子 `voided=true`。
  - RESTORE：递归把子树所有叶子 `voided=false`。
  - ADD：只允许挂在未作废的父任务下；完成/未完成父任务都可以新增。
  - INDENT：改变父子关系；拒绝缩进到作废任务下。
  - MOVE：仅象限顶层任务，整棵子树换象限，不改变父子关系。
  - OUTDENT / DELETE：结构动作，按当前状态重算父任务。
  - UNDO / REDO：文档快照，不属于状态机迁移。
- 旧数据迁移已于 2026-11-17 一次性完成；迁移代码和服务启动迁移已移除，之后只支持 `done` / `voided` 数据。
